# RFC 0001: Canonical Event Model

| | |
|---|---|
| **Status** | Draft |
| **Authors** | AttemptDB maintainers |
| **Created** | 2026-08-28 |
| **Related** | RFC 0002 (storage engine), RFC 0003 (fact/inference model), RFC 0006 (privacy and sync), `docs/storage-format.md`, `docs/compatibility-matrix.md` |
| **Normative code** | `crates/attemptdb-core/src/{ids,clock,time,event,schema,paths,privacy,codec}.rs` |

## 1. Summary

AttemptDB stores agent work as an append-only stream of **observed facts**
called events. Every provider adapter (Claude Code, Codex, Cursor, Gemini CLI,
and future agents) normalises its native hook payload into one `Event` shape.
Everything above the event — sessions, turns, spans, attempts, work units,
decisions, artifacts — is either a deterministic projection or a versioned
inference over events (RFC 0003), never a fact invented by the database.

This RFC defines the logical model precisely enough that an engineer can write
an interoperable event writer from this document plus RFC 0002 alone: the
identifiers and how they are derived, the three timestamps, the device-local
sequence number, the hybrid logical clock, the `Event` field table with stable
numeric field ids, the canonical `EventKind` set and its provider mapping, the
separation of metadata from content, unknown-field preservation, the planned
higher-level primitives, causal edge types, and the OpenTelemetry mapping.

Where this document and `attemptdb-core` disagree, the code is wrong and must
be fixed; where the code has not caught up with the plan, the item is marked
**planned**.

## 2. Scope

In scope: the logical event model and its JSON interchange encoding.

Out of scope: physical layouts (RFC 0002 and `docs/storage-format.md`), how
projections and inferences are computed (RFC 0003), the query surface (RFC
0004), the capture runtime (RFC 0005), and policy (RFC 0006).

## 3. Terminology

| Term | Meaning |
|---|---|
| Provider | A coding-agent product that emits hook payloads. Stable ids: `claude_code`, `codex`, `cursor`, `gemini_cli`; anything else is `Provider::Other(<adapter id>)` serialised as that string. |
| Adapter | Code that turns one provider's payload into canonical events. Records its own `adapter_version` on every event. |
| Hook process | The short-lived `attempt hook ...` process a provider spawns. Shares no state with other hook processes. |
| Writer | The single process holding the database write lock (normally the daemon). The only thing that assigns `source_seq`, `hlc`, and `ingested_at`. |
| Fact | An `Event`. Immutable once ingested. |
| Projection | A deterministic, replayable derivation from facts (sessions, turns, tool-call pairs). |
| Inference | A derived claim carrying confidence, evidence ids, and an algorithm/model version. |

## 4. Identity hierarchy

### 4.1 Entities and identifier types

All identifiers are 128-bit UUIDs. Text form is lowercase hyphenated
(`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`). Each identifier type has a short
display prefix used in CLI output and accepted by parsers; the prefix is **not**
part of the persisted value. `short()` renders `<prefix>` plus the first eight
hex digits of the simple form (`ev_01a04762`).

| Entity | Rust type | Prefix | Generated or derived | Status |
|---|---|---|---|---|
| Tenant | — | — | Assigned by the hosted service; absent locally | planned |
| User | — | — | Assigned by the hosted service; absent locally | planned |
| Device | `DeviceId` | `dev_` | UUIDv7, generated once per data directory and persisted in the `ATTEMPTDB` identity file | implemented |
| Project | `ProjectId` | `prj_` | UUIDv5 from repository remote, else from `(device_id, root)` | implemented |
| Repository | — | — | Represented by `ProjectRef.repo_remote`; no separate id in v1 | planned |
| Work thread | — | — | Cross-session container; not yet defined | planned |
| Session | `SessionId` | `ses_` | UUIDv5 from `(provider, provider_session_id)` | implemented |
| Turn | `TurnId` | `trn_` | Projection output; UUIDv5 from `(session_id, provider_turn_id)` when the provider supplies a turn id, else from `(session_id, first prompt event_id)` | type exists; derivation planned |
| Span | `SpanId` | `spn_` | UUIDv7 when created by an adapter; UUIDv5 from `(session_id, tool_call_id)` for tool-call spans | type exists; derivation planned |

every type. `AgentRef.agent_id` is omitted from JSON when nil.

### 4.2 Generated identifiers: UUIDv7

Events and every entity created by AttemptDB itself use **UUIDv7**
(RFC 9562): a 48-bit big-endian Unix millisecond timestamp followed by version
bits, 12 random bits, variant bits, and 62 random bits. Consequences:

- Ids sort by creation time to millisecond precision without coordination.
- Hook processes can mint event ids without contacting the daemon.
- Ids are unique across devices; no device prefix is embedded in them.
- **The embedded timestamp is not an ordering authority.** Readers order
  events by `(device_id, source_seq)` within a device and by `hlc` across
  devices (section 5). The UUIDv7 timestamp is only a tie-breaker of last
  resort and a debugging aid.

### 4.3 Derived identifiers: UUIDv5

Identifiers that must be reproducible — the same provider session seen by two
hook processes, the same repository cloned on two devices, a spool file
imported twice — are **UUIDv5** (SHA-1 name-based) under one fixed namespace.

Namespace (never change):

```text
ATTEMPTDB_NAMESPACE = 3b9ac08e-7f21-4b1d-8e5a-1c2d9f6e4a77
bytes = 3b 9a c0 8e 7f 21 4b 1d 8e 5a 1c 2d 9f 6e 4a 77
```

Name construction for a type with prefix `P` and parts `p1 … pn`:

```text
name = P || 0x1F || p1 || 0x1F || p2 || … || 0x1F || pn
id   = UUIDv5(ATTEMPTDB_NAMESPACE, name)
```

- `P` is the type's display prefix including the underscore (`ses_`, `prj_`,
  `agt_`, …). This makes derivations **type-scoped**: the same parts under two
  types yield different ids.
- `0x1F` (ASCII Unit Separator) precedes **every** part, including the first.
  A separator that cannot appear in UTF-8 text keeps `("ab","c")` and
  `("a","bc")` distinct.
- Parts are UTF-8 strings used verbatim after the normalisation rules of the
  specific derivation (below). No trimming or case folding happens inside
  `derive` itself.

Test vectors (hex of `name`, then the id):

```text
SessionId::derive(["claude_code", "abc"])
  name = 7365735f 1f 636c617564655f636f6465 1f 616263
  id   = 454a41e5-90f7-5286-b08b-ea2d1f7f806b

ProjectId::derive(["claude_code", "abc"])   (same parts, different type)
  id   = a73107b7-a0e0-5389-98ea-5a1cec84552c

SessionId::derive(["claude_code", "9f1c2b7e-3d44-4a0e-9b1a-6c7d8e9f0a1b"])
  id   = f35dc30f-10c8-5e26-8738-b66d9d51a764

ProjectId::derive(["remote", "github.com/nullarch/attemptdb"])
  id   = b2c07819-b40b-5dc6-9012-b8d1dc193b15

AgentId::derive(["session", "f35dc30f-10c8-5e26-8738-b66d9d51a764"])
  id   = 8a8cbaf9-6ead-51a9-962f-6a4ff79b0a39
```

### 4.4 Provider identifiers and the canonical session id

Provider-native identifiers are stored **alongside** canonical ones, never
replaced by them: `provider_session_id`, `provider_turn_id`,
`agent.provider_agent_id`, `tool.call_id`.

Canonical session id:

```text
session_id = SessionId::derive([provider.as_str(), provider_session_id])
```

`provider.as_str()` is the stable provider id (`claude_code`, `codex`,
`cursor`, `gemini_cli`, or the adapter id for others). `provider_session_id`
is the provider's session identifier exactly as received (Claude Code
`session_id`, Codex `session_id`, Cursor `conversation_id`, Gemini
`session_id`), untrimmed and case-preserved. Adapters that receive no session
id must synthesise one deterministically from what they have (for example
`pid:<pid>:<start-ms>`) and record `attrs.session_id_synthetic = true`.

Two sessions with the same provider session id on two devices map to the same
`session_id`; this is intended (a synced log should not split one session),
and `device_id` remains available to distinguish origins.

### 4.5 Project and agent identity

Project identity prefers the repository remote so one repository cloned in two
places maps to one project:

```text
remote  = normalise_remote(repo_remote)          # section 4.6
if remote is Some:
    project_id = ProjectId::derive(["remote", remote])
    name       = last two path components of remote joined by "/"   # owner/repo
else:
    root       = PortablePath::from_raw(raw_root, None).logical
    project_id = ProjectId::derive(["root", device_id.to_string(), root])
    name       = last path component of root (or "project" if empty)
```

`device_id.to_string()` is the hyphenated lowercase UUID text.

Agent identity:

```text
top-level agent : agent_id = AgentId::derive(["session", session_id.to_string()])
subagent        : agent_id = AgentId::derive(["agent", session_id.to_string(), provider_agent_id])   # planned
```

The subagent rule is the planned convention for adapters; `Event::new` today
sets only the top-level rule. `parent_agent_id` is the canonical id of the
spawning agent.

### 4.6 Remote normalisation

`normalise_remote` produces `host/owner/repo` without scheme, credentials,
port-insensitive handling, or `.git` suffix, lowercased:

1. Trim; empty → `None`.
2. Strip everything up to and including `://`; otherwise if the text contains
   `@`, take what follows the first `@` (scp-like `git@host:owner/repo`).
3. Take what follows the last `@` (embedded credentials).
4. Replace the first `:` with `/`, strip trailing `/`, strip a trailing `.git`,
   strip trailing `/` again, lowercase.
5. Fewer than two `/` → `None` (not a `host/owner/repo` shape).

Examples: `git@github.com:Streamize/AttemptDB.git` →
`github.com/nullarch/attemptdb`; `ssh://git@gitlab.com:2222/group/sub/repo.git`
→ `gitlab.com/2222/group/sub/repo` (the port survives as a path component; this
is a known limitation, see open questions).

## 5. Time and ordering

### 5.1 Timestamps

A `Timestamp` is a signed 64-bit integer of **microseconds since the Unix
epoch, UTC**. In JSON it is a bare integer, never a string. RFC 3339 rendering
(`2026-08-28T08:00:00.123456Z`) is a display and query-input convenience only.

### 5.2 The three event times

| Field | Assigned by | Meaning | Presence |
|---|---|---|---|
| `observed_at` | Adapter | When the provider says the fact happened (from the payload). Falls back to `captured_at` when the payload carries no time. | required |
| `captured_at` | Hook process | Wall clock of the hook process when it built the event. | required |
| `ingested_at` | Writer | Wall clock of the writer when it accepted the event into the WAL. | `None` until ingested |

`observed_at` is the time facts are displayed and queried by (`STATE … AT`).
`captured_at - observed_at` measures provider reporting delay;
`ingested_at - captured_at` measures spool/IPC delay. Both are capture-quality
metrics and are never used to reorder facts.

### 5.3 `source_seq`

`source_seq` is a `u64`, strictly increasing per **device**, assigned by the
single writer at ingestion, starting at 1. `0` means "not yet ingested" and is
what a hook process writes into a spool file. It is the authoritative order of
facts on one device: two events from the same device are ordered by
`source_seq` regardless of any timestamp. The writer persists its last issued
value in the manifest (RFC 0002) and resumes from it.

### 5.4 Hybrid logical clock

`hlc` is a `u64` packing `(wall_ms, logical)`:

```text
bit 63 ................................ bit 16 | bit 15 ........ bit 0
        wall_ms: 48 bits, Unix milliseconds     |  logical: 16 bits
hlc = (wall_ms << 16) | logical
```

Display form is `<wall_ms>.<logical zero-padded to 5>` (`1756368000123.00003`).
`0` means "not yet ingested".

One generator exists per writer and is resumed from the manifest's `last_hlc`.
Values are assigned **at ingestion**, not capture, because hook processes share
no state.

Send rule (`HlcGenerator::next(now)`):

```text
now_ms = max(now.as_millis(), 0)
if now_ms > last.wall_ms:            next = (now_ms, 0)
elif last.logical < 0xFFFF:          next = (last.wall_ms, last.logical + 1)
else:                                next = (last.wall_ms + 1, 0)
last = next
```

Receive rule (`HlcGenerator::observe(remote, now)`), used when merging events
from another writer (sync, snapshot import):

```text
wall = max(now_ms, last.wall_ms, remote.wall_ms)
if wall == last.wall_ms and wall == remote.wall_ms: logical = max(last.logical, remote.logical) + 1
elif wall == last.wall_ms:                            logical = last.logical + 1
elif wall == remote.wall_ms:                          logical = remote.logical + 1
else:                                                 logical = 0
last = (wall, logical)      # logical saturates at 0xFFFF
```

Properties: totally ordered; never goes backwards on one writer even when the
wall clock does; stays within the clock skew of physical time so it is
human-interpretable; 48 bits of milliseconds last until the year 10889.

### 5.5 Ordering rule for readers

1. Same device: `source_seq` ascending.
2. Different devices: `hlc` ascending, then `device_id` bytes ascending, then
   `source_seq`.
3. Not yet ingested (`source_seq == 0`): `captured_at`, then `event_id`.

Causal relationships between events are expressed by spans and edges (section
8), not by timestamps.

### 6.2 Nested types

**`ProjectRef`** — `{ project_id, root, name, repo_remote?, branch?, head? }`.

**`AgentRef`** — `{ agent_id?, provider_agent_id?, agent_type?, parent_agent_id?, model? }`.
Serialises as `{}` for an unassigned agent.

**`ToolRef`** — `{ name, category, call_id? }`. Categories: `shell`,
`file_read`, `file_write`, `file_edit`, `search`, `web`, `mcp`, `subagent`,
`plan`, `notebook`, `other`. `mutates_files()` is true for `file_write`,
`file_edit`, `notebook`. Shell is treated as mutating by the attempt
projection (RFC 0003) because its effect is unknown.

**`Outcome`** — `{ status, class?, exit_code? }`. Statuses: `success`,
`failure`, `denied`, `cancelled`, `unknown`. `class` is a content-free
classifier such as `string_mismatch`, `file_not_found`, `nonzero_exit`,
`timeout`, `interrupted`; it must never carry an error message body.

### 6.3 `PortablePath`

A path observed on one OS must stay meaningful on another, so a bare native
path is never persisted:

| Field | Meaning |
|---|---|
| `original` | Exactly as the provider reported it (UTF-8, lossy if needed) |
| `logical` | Forward-slash normalised. Drive letters kept and upper-cased (`C:/x`), `\\?\` prefix stripped, UNC kept as `//server/share/...`, duplicate slashes collapsed except a leading `//` |
| `repo_relative` | Relative to `project.root` when inside it; absent otherwise |
| `drive` | `C` when a drive letter is present |
| `unc` | true for UNC paths (omitted when false) |

`paths[0]` is the primary path of the event (the file edited, the file read);
tool calls touching several files list them all in order of appearance.

### 6.4 `attrs` versus `content` versus `raw`

This is the model's most important invariant:

| Field | Contents | Persisted in `metadata_only`? | May sync in `local_semantic`? |
|---|---|---|---|
| `attrs` | Allowlisted, content-free metadata only: counts, sizes, enum-like flags, hashes, logical paths. Keys and forbidden keys are enumerated in RFC 0006. | yes | yes (redacted) |
| `content` | `EventContent { prompt?, command?, message?, error?, tool_input?, tool_output?, ...extra }`. Anything that could contain a prompt, a command line, file contents, or tool output. Extra content keys are flattened into the object. | **no** (`apply_capture_mode` sets it to `None`) | no |
| `raw` | The original provider payload, verbatim JSON. | **no** | no |

Adapters must place every content-bearing value in `content`, even when the
provider labels it innocuously. A value in `attrs` longer than 256 characters,
containing a newline, or matching a secret pattern is a bug (RFC 0006 defines
the enforcement).

### 6.5 Unknown-field preservation

Top-level keys a reader does not recognise are collected into `unknown` and
re-emitted verbatim on serialisation (`#[serde(flatten)]`). Readers must not
fail on them and writers must not strip them across export/import cycles.
Inside `content`, unrecognised keys land in `extra` with the same guarantee.
Unrecognised **values** of known enums (a new `kind` string) are a
schema-version concern (section 10) and are rejected by this build, not
silently coerced — a newer writer must bump `schema_version`.

## 8. Higher-level primitives (planned)

None of the following is implemented in `attemptdb-core` beyond the id types.
They are specified here so the event model carries what they need.

| Primitive | Definition | Key fields |
|---|---|---|
| `Span` | A bounded execution range with causal parents and children. Tool-call spans pair `tool_call_started` with `tool_call_finished`/`tool_call_failed`; turn spans pair `prompt_submitted` with `turn_stopped`/`turn_failed`; subagent spans pair `subagent_started`/`subagent_stopped`. | `span_id`, `parent_span_id`, `session_id`, `agent_id`, `start_event_id`, `end_event_id?`, `kind` |
| `Attempt` | One approach toward an objective, regardless of outcome. | `attempt_id`, `work_unit_id?`, `objective` (text, content-gated), `approach_summary`, `outcome` (`succeeded` / `failed` / `abandoned` / `superseded` / `in_progress`), `superseded_by?`, `evidence: [event_id]`, `paths`, `agent_ids`, `started_at`, `ended_at?` |
| `WorkUnit` | A versioned inferred unit of project work. | `work_unit_id`, `version`, `objective`, `phase`, `status`, `confidence`, `evidence`, `artifacts`, `actors`, `edges`, `updated_at`, `inference_id` |
| `Decision` | A choice, its alternatives, evidence, and outcome. | `decision_id`, `selected`, `alternatives[]`, `evidence`, `outcome?`, `made_by` (agent or human) |
| `Artifact` | A produced output: file, commit, PR, test result, document, image, URL. | `artifact_id`, `kind`, `locator` (path / sha / URL), `produced_by` (event or attempt), `verified_by?` |
| `Inference` | A derived claim. See RFC 0003. | `inference_id`, `subject`, `claim`, `confidence`, `evidence`, `algorithm`, `algorithm_version`, `model?`, `prompt_hash?`, `valid_from`, `valid_to?`, `inferred_at`, `superseded_by?`, `superseded_at?` |
| `Correction` | A human amendment that supersedes an inference. Stored as an event, never an in-place edit. | `correction_id`, `target_inference_id`, `replacement`, `reason?`, `author`, `observed_at` |

### 8.1 WorkUnit phase and status

Phases: `EXPLORE`, `PLAN`, `IMPLEMENT`, `DEBUG`, `VERIFY`, `REVIEW`, `DELIVER`,
`BLOCKED`. Status is **independent** of phase: `active`, `waiting_on_human`,
`done`, `abandoned`, `unknown`. A unit can be `BLOCKED`/`active` (someone is
working on unblocking it) or `IMPLEMENT`/`waiting_on_human` (a permission
request is pending). There are **no numeric progress percentages** anywhere in
the model; progress is expressed only as phase, status, and evidence counts.

### 8.2 Causal edge types

Edges are directed `(from, to, type, evidence, inference_id?)` records. Types:

| Type | From → To | Meaning |
|---|---|---|
| `parent_of` | span → span, session → turn, turn → span | Structural containment |
| `caused` | event/attempt → event/attempt | A led directly to B (a failure caused a retry) |
| `triggered` | event → span/attempt | A started B (a prompt triggered a turn) |
| `blocked` | event/attempt → work unit | A put B into `BLOCKED` |
| `resolved` | event/attempt → work unit/event | A cleared the blocker B |
| `superseded` | attempt → attempt, inference → inference | B replaces A |
| `produced` | attempt/span → artifact | Output relationship |
| `verified` | artifact/event → attempt/artifact | A test or check confirmed B |
| `contradicted` | event → inference/attempt | Evidence against B |
| `handed_off` | session/agent → session/agent | Work moved between agents |
| `evidence_for` | event → inference | A supports B |

Edges from deterministic projection carry no `inference_id`; edges from
inference carry one and inherit its confidence.

## 10. Schema versioning

Two independent version numbers exist on purpose:

- **Canonical schema version** (`schema_version`, currently `1`): the shape and
  meaning of the logical event. Bumped when fields are added, renamed, or
  reinterpreted. Every event carries the version its writer used.
- **Storage format version** (RFC 0002): physical layouts of WAL frames,
  segments, manifests, and snapshots. Changes without touching the logical
  schema and vice versa.

Reader policy (`codec.rs`): accept events with
`MIN_READABLE_SCHEMA_VERSION (1) ≤ schema_version ≤ CANONICAL_SCHEMA_VERSION + 100`,
preserving unknown fields; reject anything else with `UnsupportedSchema`.
Adding an optional field or a new `attrs` key is a compatible change and does
not require a bump. Adding an `EventKind` variant, a `ToolCategory`, or an
`OutcomeStatus` requires a bump because older readers cannot parse the value.
A JSON Schema document for the interchange encoding is planned and will be
generated from the Rust types.

## 11. JSON interchange encoding

The v1 interchange codec is UTF-8 JSON (`CodecId::Json = 1`) with string field
names, produced by `serde_json` from the Rust types. Rules:

- Optional fields are **omitted** when absent, not written as `null`.
- Defaults are omitted where marked (`source_seq`/`hlc` are written even when
  0; `paths`, `attrs`, `unknown` are omitted when empty; `agent` is always
  present).
- Key order is not significant; writers should emit the order below.
- Timestamps are integers (microseconds); `hlc` and `source_seq` are integers.
- UUIDs are hyphenated lowercase without display prefixes.

## 12. Writer conformance checklist

An interoperable writer must:

1. Mint `event_id` as UUIDv7 and never reuse one.
2. Set `schema_version = 1`, `device_id` from the identity file,
   `source_seq = 0`, `hlc = 0`, `ingested_at` absent.
3. Set `observed_at` from the payload or equal to `captured_at`.
4. Derive `session_id`, `project.project_id`, and `agent.agent_id` exactly as
   in section 4 and keep the provider ids alongside.
5. Map the provider event name per section 7; use `unknown` rather than
   dropping; keep `provider_event_name` verbatim.
6. Put nothing content-bearing in `attrs`; put it in `content`; honour the
   capture mode before writing anything to disk.
7. Normalise every path through the `PortablePath` rules.
8. Encode with the v1 JSON codec and frame it per `docs/storage-format.md`.
9. Preserve unknown fields on read-modify-write.

## Decisions

- Identifiers are UUIDs; generated ids are UUIDv7, derived ids are UUIDv5 under
  the fixed namespace `3b9ac08e-7f21-4b1d-8e5a-1c2d9f6e4a77` with the
  `<prefix>` + `0x1F`-prefixed-parts name construction. Display prefixes are
  not persisted.
- Session identity is `(provider, provider_session_id)`; project identity
  prefers the normalised remote and falls back to `(device_id, logical root)`.
- Three timestamps (`observed_at`, `captured_at`, `ingested_at`) are stored as
  microsecond integers; ordering uses `source_seq` within a device and the
  packed 48+16-bit HLC across devices, both assigned by the single writer at
  ingestion.
- `attrs` is content-free by construction; `content` and `raw` are
  capture-mode gated and never present in `metadata_only`.
- Unknown top-level fields survive read/write cycles; unknown enum values do
  not and require a schema-version bump.
- Unmapped provider events become `unknown` and are never dropped.
- Canonical schema version and storage format version are independent.
- WorkUnit phase and status are independent; no numeric progress is modelled.
- Field numbers in `schema.rs` are permanent; names are not.

## Open questions

- `agent.provider_agent_id` and `outcome.exit_code` are serialised and have
  segment columns (RFC 0002) but have no `field_id` constants. Proposed:
  `PROVIDER_AGENT_ID = 84`, `EXIT_CODE = 132`. Needs a code change before the
  first binary encoding ships.
- Should `normalise_remote` drop an explicit port (`gitlab.com:2222/...`)
  instead of keeping it as a path component? Changing it changes project ids.
- Turn id derivation when the provider supplies no turn id: first prompt
  `event_id` is deterministic only after ingestion order is fixed; confirm.
- Whether `Provider::Other` adapter ids need a registry to avoid collisions
  between community adapters.
- Whether `agent_message` should be captured from hooks that expose
  `last_assistant_message` (content-gated) or only from transcript import.
- Tenant/user/work-thread identifiers: define now as optional fields or wait
  for the hosted sync RFC to need them.
- JSON Schema generation: hand-written or derived from the Rust types via
  `schemars`.
